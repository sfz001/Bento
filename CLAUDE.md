# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Bento** — personal macOS menu bar toolkit (Swift + AppKit). A grab-bag of small utilities the owner uses daily. Current modules:
1. **Remote screen-off** — when a RustDesk or macOS Screen Sharing (VNC) connection is detected, the local screen goes black for privacy; on disconnect, the screen restores and locks.
2. **Scroll direction control** — Mos-style independent scroll-direction reversal for mouse vs trackpad.
3. **Window tiling (分屏)** — MaxTo/Moom-style per-monitor split layouts, edited via a WYSIWYG full-screen overlay editor on each real display, persisted per-display (keyed by CGDisplay UUID) in `~/Library/Application Support/Bento/config.json`. Gestures: **double-click a titlebar** = snap the window into the cell under the click point (double-click again while in the cell = restore); **Shift + double-click** = maximize to the screen; **Shift + drag a titlebar** = snap to the cell highlighted on a grid overlay; **wiggle a titlebar** (fast back-and-forth) = maximize to the screen; a plain drag or edge-resize cancels the snap state.
4. **Menu bar icon manager (菜单栏图标管理)** — Bartender/Ice-style selective hide/show of menu bar icons: menu opens a checklist window (NSTableView) listing every third-party icon by owning app **plus movable system modules** (Battery/Wi-Fi/User Switching; Clock and Control Center are pinned by the system and excluded) **plus Bento's own icon** (sortable, not hideable); unchecking hides an icon into the system "«" overflow section, checking shows it again; rows are **drag-reorderable** and the row order is applied to the real menu bar (persisted as `MenuBarIconOrder`). Moves use one of two auto-selected levers: rewriting `com.apple.MenuBarAgent`'s `TrailingItemPreferredPositions` plist (macOS 27 Beta 4 — no synthetic drags), or synthetic ⌘-drags (Beta 5+ — the dict became write-immune; see the module section). There is no forced-hide primitive on 27, so on a roomy bar hidden items can become visible again. Hidden keys persist in UserDefaults (`HiddenMenuBarItemKeys`) and change **only** through the manager UI.
5. **Sleep guard (防止睡眠)** — Caffeine/Amphetamine-style keep-awake. Exactly two plain menu rows: **永久防睡** (checkmark toggle) and **定时防睡 ▸** (30 min / 1 h / 2 h / 4 h presets, then 防睡设置… which opens a window for custom minutes, allow-display-sleep mode, and low-battery auto-stop). Backed by a single `IOPMAssertion`; state is deliberately **not** persisted across launches.

The project began as `RustDeskScreenOff` (remote screen-off only) before growing into Bento; repo/dir/app/bundle are all `Bento` now.

## Build & Run

```bash
./build_app.sh             # Compile arm64, package .app bundle (icon from Assets/AppIcon.icns)
./build_app.sh --check     # Seconds-fast typecheck only — no binary, no bundle
BUILD_UNIVERSAL=1 ./build_app.sh   # arm64 + x86_64 universal binary
open Bento.app             # Run
```

Build requires macOS 14.0+ SDK. Uses `swiftc` directly (no Xcode project/SPM). Frameworks: AppKit, CoreGraphics, IOKit (IOKit is used only by ScrollReverser).

## Architecture

Code lives in `Sources/`, one file per module, compiled together by `build_app.sh` (`swiftc Sources/*.swift`; top-level entry statements must stay in `main.swift`):

- `Sources/Support.swift` — shared `runProcess` helper + `ErrorLog`. Two non-obvious guarantees live here: `runProcess` **always returns** (a watchdog SIGTERMs, then SIGKILLs, a child that outlives `timeout`, default 10s — otherwise `readDataToEndOfFile`/`waitUntilExit` pins the calling thread forever and the poll queue dies silently while timer events pile up), and `ErrorLog.logSync` checks a `DispatchSpecificKey` before `queue.sync` (a crash *inside* the log queue — `FileHandle.write` raises on a full disk — would otherwise wait on itself: no abort, no log)
- `Sources/ScreenController.swift`, `Sources/ScrollReverser.swift`, `Sources/WindowTiling.swift`, `Sources/MenuBarIconManager.swift`, `Sources/SleepGuard.swift`, `Sources/AppDelegate.swift` — the modules below
- `Sources/main.swift` — single-instance guard, uncaught-exception logging, NSApplication bootstrap

File-scope `private`/`fileprivate` declarations don't cross these file boundaries — anything shared between modules belongs in `Support.swift` as internal.

- **`ScreenController`** — Screen blackout via `CGSetDisplayTransferByFormula` (gamma to zero), restore via `CGDisplayRestoreColorSyncSettings`, lock via `open -a ScreenSaverEngine`. Note `CGDisplayRestoreColorSyncSettings` restores the ColorSync/factory settings of **every** display, so a hand-tuned gamma calibration on an external monitor is reset along with the blackout — inherent to the gamma technique, no per-display undo exists. Multi-monitor mirroring via `CGConfigureDisplayMirrorOfDisplay` (merge on connect, restore on disconnect). Resolution switching to 1512x982 HiDPI on connect, Dock repositioning (moves to left on connect, restores original position/autohide on disconnect). Gamma is invisible to ScreenCaptureKit so remote viewers see normal desktop.
  - **All three mutations persist a snapshot in `UserDefaults` and follow the same rules: snapshot saved BEFORE the mutation is applied (a SIGKILL between apply and cfprefsd flush must not leave the mutation un-undoable; the resolution path once had this backwards), an existing snapshot is never overwritten, cleared only on a successful restore, and an undecodable snapshot is logged + deleted on load (a poisoned key would otherwise both block new saves via the never-overwrite rule AND never restore — silently killing the whole recovery subsystem).** `BentoMirrorSnapshot` (mirror targets), `BentoDisplayModeSnapshot` (original mode as width/height/pixel size/refresh **plus the display's UUID via `DisplayKeys`** — restore resolves the display by UUID rather than assuming "current main", since main can change between a crash and relaunch; target display offline → snapshot kept and restore deferred, mode no longer in the display's list → snapshot dropped; re-looked-up in `CGDisplayCopyAllDisplayModes` since `CGDisplayMode` isn't serializable), `BentoDockSnapshot` (orientation + autohide). The Dock half also runs on its own serial `dockQueue` — 2 `defaults read` + 2 `defaults write` + `killall Dock` is five process spawns, and the connect/disconnect decision is made on main; `savedDockOrientation`/`savedDockAutohide` are confined to that queue, and **`applicationWillTerminate` must call `waitForPendingDockWork()`** or the process exits before the Dock moves back. Reason for the never-overwrite rule: gamma dies with the process but resolution and Dock don't, so a SIGKILL/crash mid-session leaves them applied; the next connect would otherwise snapshot the *already-modified* state as "original" and permanently cement 1512x982 + left Dock. `recoverFromUncleanExit()` runs from `applicationDidFinishLaunching` (before the poll timer starts) and rolls back resolution + Dock if snapshots survive. Mirroring keeps its own path — the first poll's edge-triggered cleanup plus 恢复扩展显示器 as a manual fallback.

- **`ScrollReverser`** — Independent scroll-direction control (Mos-style). Installs one session event tap for both two-finger gesture detection and scroll-wheel delta rewriting. Trackpad vs mouse follows Scroll Reverser’s approach: non-continuous scrolls are mouse, recent 2+ finger gesture scrolls are trackpad, momentum continues with the previous source. Reverses line/fixed-point/point delta axes when enabled, setting point deltas last to preserve smooth scrolling, and also rewrites the underlying IOHID scroll fields for apps that read those. Defaults: mouse reversed (ON), trackpad untouched (OFF). Persists toggles in `UserDefaults` (`ReverseMouseScroll`, `ReverseTrackpadScroll`). Self-heals on `.tapDisabledByTimeout`, rebuilds the tap on wake/session-active, and a 5s watchdog re-enables it if found disabled. Requires Accessibility and Input Monitoring permissions; if denied, Bento shows a warning alert, exposes menu actions to open the relevant System Settings panes, disables scroll toggles with "(Grant Permissions)", and allows retrying without relaunch.

- **`AppDelegate`** — Orchestrates everything. Every 3 seconds polls for active connections: `pgrep -fi "rustdesk.*--cm"` for RustDesk, and `netstat -an -p tcp` parsed in Swift (local column ending `.5900` + ESTABLISHED) for macOS Screen Sharing — no shell/awk pipeline. **Probes are three-state** (`connected`/`disconnected`/`unknown`): spawn failure, watchdog kill, or empty netstat output is `unknown`, which keeps the current state and never restores the screen — collapsing failures into "no connection" once meant a transient glitch un-blacked the desktop mid-session. **Disconnect confirmation only consults the probe of the source that activated the session** (`activeSource`) — the netstat probe can be *permanently* unknown (child processes on this machine get an empty TCP table from `netstat -an -p tcp`; cause unresolved), and requiring both probes definite would leave a finished RustDesk session black forever. A probe that can never see a connection can't have been the session's activator, so ignoring it is sound. The idle-side mirror cleanup runs whenever neither probe is definitely connected (it's an idempotent snapshot-guarded no-op) so startup mirror recovery isn't blocked by a permanently-unknown netstat. Restore requires **2 consecutive definite source-probe disconnects**, then runs lock-first: `lockScreen()` immediately, gamma/resolution/dock/mirroring restore 1.2s later via a cancellable `pendingRestore` work item (reconnect cancels it) — the old restore-then-lock order exposed the real desktop until the screensaver engaged. Heavy setup (mirroring/resolution/dock) is gated by `sessionPrepared`, separate from `isScreenBlack`, so a partially-failed `setBlack` retries gamma every tick without re-running `killall Dock`. Both `didChangeScreenParameters` AND `NSWorkspace.didWake` observers re-mirror and re-assert gamma while black (hot-plugged display would otherwise show the live desktop; some machines reset gamma tables on wake and a single-display wake doesn't guarantee a screen-params notification). The delayed-restore work item carries a `restoreGeneration` token in addition to being cancellable — cancel can't reach a work item that already started or one of several piled up behind a stalled main thread. Idle mirroring cleanup is edge-triggered (first poll + connected→disconnected), not every tick. Manages the all-Chinese NSStatusItem menu (FileVault 免密重启, screen-off controls, etc.) — grouped with macOS 14 `sectionHeader` items (no separators before headers — the header IS the section divider; only the trailing general section keeps one); note **macOS 27.0 (build 26A5388g) ignores `NSMenuItem.image` entirely** — not just visually: `NSMenu.size` is byte-identical with no image, with an SF Symbol, and with a 64×64 bitmap (136×34 in all three), so AppKit reserves no layout space at all. It is not a status-item-specific rendering path. Older macOS still draws them (confirmed on another machine running the same commit), so the symbol assignments stay. If icons are ever wanted on 27, the only working route is `attributedTitle` + `NSTextAttachment` (measured: widens 136 → 162), at the cost of hand-tinting the attachment on highlight since attachments don't follow `selectedMenuItemTextColor`. `state = .on` still lays out normally (136 → 150), so checkmarks are unaffected. Also carries scroll-reverse toggles and the tiling section. Login auto-start uses `SMAppService.mainApp` (registered on first launch; afterwards the 开机自启 menu toggle owns it); a one-time migration unloads and deletes the old hand-written `~/Library/LaunchAgents/com.sz.bento.plist`.

- **Tiling module** (`MARK: - Window Tiling` section) — key pieces:
  - `CoordConv` — the ONLY place AppKit (bottom-left origin) ↔ CG/AX (main-screen top-left origin) conversion happens. Never flip y elsewhere.
  - `LayoutNode` — recursive binary-split tree (`cell` / `split(dir:V|H, ratio, a, b)`), defensive Codable (bad ratio→0.5, missing node→cell, corrupt JSON→default + error.log).
  - `TilingConfig` — JSON persistence; display layouts keyed by CGDisplay UUID (`DisplayKeys`), never displayID/screen index.
  - `WindowManager` — CGWindowList geometry prefilter (titlebar band, 28pt; window list cached ~80ms so click bursts and the Shift-double-click double-query share one enumeration) before any AX call; `setFrame` writes **size → position → size** (position-first gets clamped by apps that re-fit on-screen bounds, e.g. Ghostty/Terminal), up to 3 rounds with 60ms settle waits between (some apps apply frames **asynchronously** — the immediate read-back shows the new size with the old position), then **per-axis re-writes**: whichever of position/size is still off after the rounds gets one more targeted write (apps partially apply — size lands but position is reverted, or vice versa). Early-return tolerance is 4pt — app pixel rounding (855 vs 851.24) must not trigger redundant rounds, or the window visibly "nudges twice". `axWindow` matches by `_AXUIElementGetWindow` windowID first, frame-proximity fallback; snappable = standard subrole, not fullscreen/minimized, size-settable.
  - `TilingController` — session event tap (leftMouseDown/Up/Dragged; mouseMoved is deliberately NOT subscribed — Shift-drag emits leftMouseDragged, and a mouseMoved subscription would wake the process on every mouse move for nothing). Gesture table (all on the titlebar; the left ~80pt traffic-light zone is EXCLUDED from every action — eating the 2nd click there breaks the close/minimize buttons' multi-click tracking):
    | Gesture | Behavior |
    |---|---|
    | double-click | snap into the cell containing the click point; double-click again while in the cell = restore |
    | Shift + double-click | REAL maximize (fill the current screen's `visibleFrame`, not a fullscreen Space); always maximizes, never restores |
    | Shift + drag | snap to the cell highlighted on the grid overlay (overlays appear on the first drag movement, not on the down — otherwise Shift-double-clicks flash the grid) |
    | wiggle (fast back-and-forth) | REAL maximize; always maximizes, never restores |
    | plain drag ≥6pt / edge resize | cancel the snap state (the next double-click re-snaps) |
    - The wiggle detector: a plain titlebar drag with ≥2 direction reversals (consecutive segment angle ≥120°, segments ≥12pt, total travel ≥60pt, all within 1.2s — tuning knobs in `updateWiggle`/the up-handler). The wiggle cancels any cell-snap state like any other drag; Shift-double-click keeps it (so a later plain double-click snaps back to the cell and the original restore chain stays intact).
    - **Double-click detection has a self-tracked fallback**: the system occasionally delivers BOTH clicks of a double-click as clickState=1 (invisible in logs — looks like "nothing executed"), so a second same-spot down inside `NSEvent.doubleClickInterval` is treated as a double-click even when the system says it isn't (the candidate records whether Shift was held; a drag consuming the first click clears it).
    - **Double-click target cell = the cell containing the click point** (a window spanning several cells goes to the cell the user actually clicked in the titlebar, not the max-overlap cell — overlap-guessing sent spanning windows into the wrong cell with the right edge overflowing into the neighbor); max-overlap is only the fallback when the point sits on a divider/gap.
    - **"Is this window maximized?" is judged against the CELL, not the recorded snap frame** (tolerance 4): double-click restores only while the window sits exactly in its cell; any moved/resized window (even by a little, even with a surviving memory record) gets re-maximized on double-click.
    - **A plain titlebar drag ≥6pt, or an edge-zone resize (down in the ~12pt border, size actually changed per AX — so scrollbar drags in the same zone don't count), invalidates that window's snap memory on mouse-up** — user geometry edits are themselves the "un-maximize" gesture (tracked geometrically from the tap, zero AX cost on the normal path).
    - Snap memory stores (original, actual-snapped) frames per CGWindowID (`_AXUIElementGetWindow` private API); restore clamps to nearest screen if the original display is gone. **Cell snap writes track settling with fast but capped correction**: settle re-reads at 0.35/0.7/1.2/2.8s (stamp-guarded) update the recorded frame; the 0.35s and 1.2s checks may re-issue the frame write when still >6pt off (a partially-applied write leaves the window visibly broken — correction must come fast, ~0.35s), the others only record so the app gets a beat to apply each write. Rewriting too eagerly makes the window visibly drift (interrupts async settle animation); rewriting too late (the 3.2s-only version) left the broken state hanging ~3s — worse. **Maximize writes (wiggle/Shift-double-click) get the same tracking, faster** (`writeFrameTracked`: re-writes at 0.15/0.7s, tolerance 6 — without it, async-applying apps showed only a "weird enlargement" (size applied, position lost) and needed a second wiggle).
    - A global `layoutStamp` (bumped by snaps/restores/wiggles/maximizes/manual drags) cancels in-flight settle tracking so a pending rewrite can't clobber the user's next action.
    - **All frame writes run on a dedicated serial `layoutQueue`** — `setFrame`'s retry sleeps (3 rounds × 60ms) and the settle re-writes would block the main thread for ~300ms otherwise; state mutations (`snapMemory`, `layoutStamp`) still happen on main via `onLayoutQueue` callbacks, guarded by stamps so a stale callback can't clobber a newer action. The Shift-double-click maximize reuses the already-resolved window+frame (`maximizeToScreen`) instead of a second AX lookup.
    - AX negative cache TTL is 0.4s (a long TTL silently swallows the follow-up double-click = "nothing executed"). Watchdog re-enables/rebuilds the tap; wake/unlock rebuilds it and resets all click state; `didChangeScreenParameters` closes the editor and invalidates display-key cache. The status menu's tiling section carries a disabled hint row (双击=吸进格子 · Shift双击=铺满屏幕 · Shift拖=网格吸附 · 甩动=铺满屏幕) so the gestures stay discoverable.
  - `LayoutEditorSession` — one borderless editor window per screen covering exactly `visibleFrame` (menu bar/Dock stay clickable), floating toolbar with grouped buttons (保存并应用 = accent primary, rightmost; no `.hudWindow` — HUD restyles buttons and swallows bezelColor), right-click split/merge menu, divider dragging clamped to 0.08–0.92 with hover highlight + resize cursor rects, hint pill drawn at the bottom (top belongs to the toolbar), Esc cancels / Return saves (local keyDown monitor — the panel's keyEquivalent can't fire while an editor window is key); only 保存并应用 writes config.
  - Uncaught exceptions append to `~/Library/Application Support/Bento/error.log` (serialized writes; rolls to `error.log.1` past 256KB; the crash handler uses `ErrorLog.logSync` — an async enqueue would be lost when the process aborts); single-instance enforced in main.

 - **Menu bar icon manager** (`MARK: - Menu Bar Icon Manager` section) — **DISABLED as of 2026-08-14: `MenuBarIconManager.featureEnabled = false`** (owner decision: the Beta 5 drag workflow — expand strip / synthetic drag / collapse / verify per action — turned out more cumbersome than manual ⌘-drag, so the module was turned off; the code and this documentation stay for a potential re-enable, which is just flipping that constant back to `true` — menu entry, 3s enforcer, and quit-restore all come back). When enabled, it targets the macOS 27 menu bar architecture and no-ops when the MenuBarAgent process is absent, i.e. on macOS ≤26 (the 26-era ControlCenter-hosted / synthetic-⌘-drag "scromble" implementation was removed; see git history if ever needed). **Two levers, auto-selected:** the *dict lever* (Beta 4 ≤26A5388g: `TrailingItemPreferredPositions` writes are consumed) and the *drag lever* (≥26A5406e: synthetic ⌘-drags, because — verified 2026-08-13 with controlled writes — the dict is accepted by cfprefsd but **never consumed by the agent**; the real bar ignores it completely, so every dict-based correction is a no-op that spins forever). Lever selection in `start()`: build ≥ `26A5406e` → drag; unknown future builds start on dict and **permanently switch to drag after 3 consecutive reality-correction rounds that fail to converge** (drag mode is always correct, just noisier). Key facts:
   - macOS 27 hosts the whole menu bar in a dedicated `MenuBarAgent` process (sandboxed since Beta 5; container prefs empty, internal layout store location unknown): no per-icon CG windows. Item layout *used to* live in `com.apple.MenuBarAgent`'s `TrailingItemPreferredPositions` dict: key `status:<signing-id>::<autosaveName>` (bundleID for properly signed apps, executable name for ad-hoc) or `module:<Name>` for system modules; value = preferred distance from the right edge (bigger = further left). Beta 4: external writes apply live via cfprefsd, values are pure rank weights, the agent re-packs on dict writes / status-item churn and occasionally rewrites the dict with self-computed actual distances (transient overflow coordinates included — position values are NEVER adopted as hide/show intent; doing that once mass-corrupted `HiddenMenuBarItemKeys`). Beta 5: the dict is dead weight — **drag mode never writes it**.
   - **Drag lever primitives (all verified on 26A5406e):** manual-style synthetic ⌘-drag moves items and the result persists in the agent's private store (survives kills and cfprefsd flushes). A drag = warp cursor to source center → `leftMouseDown` with `.maskCommand` flag → ~10 `leftMouseDragged` steps warping toward the target → `leftMouseUp` (⌘ released) → restore cursor; posted at `.cghidEventTap`. **No mid-drag grab verification exists or can exist: during a drag the entire AX tree is byte-identical (buttons/modules/extras all frozen until the drop lands)** — any live-motion check is pure noise (false negatives, plus ticker-width re-packs that false-positive). Correctness comes from fresh source-frame reads, a 2s settle + post-drag frame-change check per op ("拖后 frame 未变" = grabbed the wrong object / drop bounced → stop the round), and post-collapse verification. **All synthetic input (warp + posts) must be bridged to the main thread via `onMainSync`** — the same sequence posted from a GCD queue thread is silently dropped by the window server (verified; the bridge blocks with a semaphore and `prepareForQuit` waits with RunLoop spinning so the bridge can't deadlock).
   - **Strip expand/collapse:** the "«" chevron is `AXButton` desc `显示隐藏菜单栏项目` (collapsed; click = expand) / `隐藏菜单栏项目` (expanded; click = collapse) in the agent's **live window** — the agent exposes 3 AX windows; the live one is the only one whose wrappers contain `AXButton` children (the other two are collapsed-view `AXApplication` placeholders), and only its content tracks the current state. **The chevron position drifts between passes — always re-read the rect immediately before clicking** (stale coordinates hit the ticker or a ghost). Every synthetic click is preceded by an ESC (a mis-dropped up can leave a status-item menu open, which swallows subsequent chevron clicks). AXPress on the chevron returns -25206 (unsupported). **Beta 5 never auto-collapses the strip**; the enforcer collapses a user-opened strip only after a 60s grace (so a user who expanded to drag manually isn't fought) — collapsed-state frames are the only reliable evaluation input.
   - **Expanded state = the drag workspace.** Expanded, every item gets a unique real frame: third-party items via each app's own `AXExtrasMenuBar` (identity + frame — this is how strip items are identified, since the live window's strip buttons are untitled), system modules via `AXMenuBarItem` `com.apple.menuextra.*`, Bento via `AXButton` desc `Bento`. Visible items keep their bar positions; overflow items spread leftward in the strip region (x ≈ 150-600). Drag semantics: **dropping into the strip region = hide (joins the overflow set); dropping at the right-end gap = show** (clean insert when a gap exists; otherwise the agent shifts the chain left and the leftmost visible sinks — crowded-bar semantics). Inserting onto an occupied slot rotates the chain `[drop..origin)` toward the origin (verified) — that rotation is what sinks the leftmost item, so show-drops target the right end, never an occupied slot.
   - **Correction session** (`runDragCorrection`, on the enforcer's queue, reentrancy-guarded, skipped while Bento's status menu is open): compute 该隐未隐/该显未显 from **collapsed-state** frames → expand (only if membership work is needed) → hide each (drop into strip) → show each (drop at right end, in desired order) → collapse → wait 3.5s for the re-pack to settle → verify and log residuals. **Order fixing runs only on UI-triggered rounds** (`enforceOrder`) and only in the collapsed state — the expanded x-order is wrong for wide items (the 200pt ticker's expanded slot sits inside the strip region, so an expanded-order comparison once dragged a freshly-shown item straight back into overflow). On drift rounds the order self-adopts from the real bar on the next pass (the bar is the source of truth for ordering, never the persisted list). Per-key give-up after 3 failed rounds (`dragGiveUp` — the system-zone Siri/`systemuiserver` items genuinely can't be dragged; they're observation-logged instead), cleared on UI actions.
   - **Crowding acceptance:** when the total width of intended-visible items exceeds the on-bar width by >30pt, the bar is genuinely full (the agent's pack limit + a 200pt ticker); the sunk keys go into `acceptedSunk` (logged once) and stop triggering corrections — otherwise shows/hides round-robin the leftmost item forever. Cleared when space frees up or on UI actions.
   - **on-bar judgment** (`onBarCollapsed`, used by adoption, reality check, session): y∈[0,44], x within the main display, width>0, AND not a ghost — collapsed-overflow items get ghost frames stacked exactly on the chevron (`AssignCollapsedOverflowFramesPass`), which look perfectly on-bar. The guard is **narrow + hugging the chevron** (`width ≤ 90 && minX > chevron.minX - 36 && intersects`) because the ticker legitimately *spans* the chevron (the boundary cuts through its 200pt width) — a naive intersects-check once false-flagged the visible ticker as sunk. The check is skipped when no item has any frame (the agent's AX tree is empty while the display sleeps).
   - System modules are managed through the same identity (`moduleKeyMap`: Battery/WiFi/Clock/UserSwitcher/BentoBox/NowPlaying). **Verified PINNED (not even draggable): Clock and Control Center** (`module:BentoBox` — Apple's internal name, coincidentally) — never shown as rows. In drag mode battery/WiFi/UserSwitcher/NowPlaying are fully draggable (WiFi and battery both verified moving out of overflow); in dict mode battery is de-facto pinned (Beta 5 ignores `module:Battery` writes; `com.apple.controlcenter` grew `NSStatusItem Preferred Position X` / `VisibleCC X` keys + `HasAttemptedMenuBarWorkflowMigration=1` — revisit if a later beta consumes them). New keys with no prior intent adopt their real membership (in-bar → visible, sunk → hidden) instead of defaulting visible.
   - Entry-key resolution (dict mode only) writes to exactly ONE prefix per app (the one with existing dict entries; bundleID synthesized only when none exist — nearly all third-party menu apps are properly signed; Bento's own ad-hoc prefix is the executable name). Pairing ladder: unique existing key → index pairing on equal counts → Item-N suffix matching → skip writes + log once per app (writing to a wrong key is worse than not writing). Phantom keys under the losing prefix are garbage-collected on the next rewrite.
   - Menu-quit (退出 Bento) calls `prepareForQuit()`: dict mode writes hidden entries back to a visible band; drag mode expands once and drags each hidden item to the right end (9s budget, best effort). `HiddenMenuBarItemKeys` is kept, so a relaunch re-hides them. Deliberately NOT in `applicationWillTerminate` — restarts/shutdowns pass through there and each would add status-item churn (the known agent-rewrite trigger). `prepareForQuit` waits with RunLoop spinning, not a parked semaphore — the drag path's `onMainSync` bridge needs the main queue draining.
   - Identity still comes from each app's `AXExtrasMenuBar` (title/desc); persistence keys are `bundleID|index`, never titles (WeChat badge titles are volatile). `pidByKey` (key → pid) is refreshed in `enumerateItems` for the drag lever's live-frame reads.
   - No AX permission = `enforce` returns immediately, so the module is otherwise completely silent. It publishes `needsAccessibility` to main in that branch and the manager window's empty state switches to a 需要辅助功能权限 message plus a button into the Privacy pane — without it the window just says 未识别到菜单栏图标 and reads as a bug.
   - **Threading contract: the model state (`hiddenKeys`, `iconOrder`, `iconNames`, `lastEntryKeys`, `acceptedSunk`, `dragGiveUp`, the AX/bundle caches) is confined to the enforcer's serial queue.** UI actions (row switch, 全部恢复显示, drag reorder) only post intent with `queue.async`; the queue publishes immutable `[Row]` snapshots back to main via `publishRows`. `rows` and `rowIconCache` are the mirror-image case — main-thread only. This is not stylistic: those collections were being mutated on main while the 3s pass enumerated them on the queue, and Swift's Set/Array/Dictionary have no concurrent-access guarantee. Also note `byKey` is built with `uniquingKeysWith:`, not `uniqueKeysWithValues:` — two instances of one app (`open -n`, two copies) produce duplicate `bundleID|index` keys and the latter traps.
   - Enforcer runs every 3s on a serial queue, gated by a (positions-dict + running-apps) signature, with a 60s forced full pass as fallback (the reality check + drag corrections run on that 60s cadence plus immediately on UI actions). Per-pass AX cost is bounded: pids confirmed to have no menu-bar extras are skipped on regular passes (re-probed only on the 60s pass), CFBundleName lookups are cached, and `iconOrder`/`iconNames` are batch-assigned so UserDefaults is written at most once per pass (`iconNames` stores only the stable app name, never volatile ticker/badge text). Visible-item ORDER is adopted from the real bar every pass (dict positions in dict mode, collapsed AX frames in drag mode — never enforce a stale persisted order; that silently rearranges the user's bar). Dict mode only rewrites on semantic mismatch (should-be-hidden visible, wrong visible order, missing entries), never over numeric drift — avoiding write-fights with the agent. UI-triggered rounds set `suppressAdoptionOnce` so a just-dragged row order isn't immediately overwritten by pre-drag positions.

- **Sleep guard** (`Sources/SleepGuard.swift`) — keep-awake via a single `IOPMAssertion`. Verified facts (macOS 27.0):
  - `import IOKit.pwr_mgt` is required — bare `import IOKit` exports no `IOPMAssertion*` symbols. Type/property key constants are Swift `String` (not `CFString`), so they drop straight into a `[String: Any]` for `IOPMAssertionCreateWithProperties`.
  - **One assertion, never two**: asserting `PreventUserIdleDisplaySleep` also blocks system idle sleep. `kIOPMAssertionTypePreventSystemSleep` is a no-op (SDK header says "not supported"; `caffeinate -s` behaves the same).
  - Timed sessions set `kIOPMAssertionTimeoutKey` + **`TimeoutActionRelease`** as a hard backstop so a wedged/SIGKILLed Bento can't pin the machine awake. `TimeoutActionTurnOff`/`Log` are useless here — after they fire, `IOPMAssertionCopyProperties` still reports `AssertLevel=255`, so the app can't detect expiry; only `Release` makes it return nil. Because powerd's timeout and the local wall-clock timer name the *same instant*, the expiry handler (`handleExpiry`) probes the assertion with `IOPMAssertionCopyProperties` first and passes `release:` accordingly — same liveness test `reconcile` uses, for the same reason (recycled IDs mean re-releasing a dead one can kill somebody else's assertion).
  - Every timer uses `wallDeadline:` — `DispatchTime`/`Timer` ride the mach monotonic clock, which freezes across sleep (measured ~44h skew on this machine). Wake/session-active triggers `reconcile()`, which trusts the wall-clock deadline over everything else. When powerd already released the assertion, the local teardown must **skip `IOPMAssertionRelease`** — `IOPMAssertionID`s are recycled handles and re-releasing a dead one can kill somebody else's assertion.
  - Assertion name must be ASCII or `pmset -g assertions` renders `named: ""`. powerd reclaims assertions on process exit (incl. abort/SIGKILL), so there is deliberately no `prepareForQuit`.
  - Active state is **not** persisted (no `SleepGuardEnabled` key): restoring "keep awake forever" on login is a silent battery drain, and the assertion doesn't survive the process anyway. Persisted prefs are only `SleepGuardMode` / `SleepGuardDefaultMinutes` / `SleepGuardBatteryStopPercent`.
  - Idle cost is zero timers in the default config (indefinite + battery-stop off); the 60s tick exists only to refresh countdown text or poll battery, so it is created only when one of those is live.
  - **Menu interaction is deliberately plain `NSMenuItem`s.** An earlier version put a custom `NSMenuItem.view` on one row to tell single-click (toggle) from double-click (settings) — NSMenu has no native double-click. It worked but cost an optimistic-UI state machine, a mouseDown-anchored double-click window, a highlight-forwarding menu delegate (custom views don't self-highlight, and an item with no action is auto-disabled by `autoenablesItems`, which silently kills highlight + keyboard nav + accessibility), and runtime probing of menu item height/text inset. Two ordinary rows carry the same intent with none of it. Don't reintroduce the custom view.
  - `AppDelegate` is `statusMenu.delegate`: `menuNeedsUpdate` refreshes the countdown text, `menuWillOpen` puts the tiling tap on hold, `menuDidClose` releases it. The split is deliberate — `NSMenu.h` says "Do not modify the structure of the menu or the menu items from within these callbacks" about willOpen/didClose, and the countdown rewrites 定时防睡's title; `menuNeedsUpdate` is the sanctioned hook and fires before `menuWillOpen`, so the menu is measured with the new text. **That hold is load-bearing** — `WindowManager.onScreenWindows()` filters to `layer == 0` and `pid != myPid`, so Bento's own menu window is invisible to the tiling tap; without the hold the tap judges clicks that land on the menu against whatever window happens to sit *underneath*, swallowing them and snapping an unrelated window. `TilingController.setMenuTracking` stores a `Date` rather than a `Bool` so a lost `menuDidClose` can't disable tiling permanently (2 min backstop).
  - New file-crossing top-level symbols to avoid re-declaring elsewhere: `SleepGuard`, `SleepGuardMode`, `SleepGuardSettingsWindow`.
  - Can **not** stop clamshell sleep — no non-kext mechanism exists on Apple Silicon, and `pmset -a disablesleep` needs root. The settings window says so instead of pretending.

- **Main entry** — Creates `NSApplication`, sets delegate, calls `app.run()` (no storyboard/NIB).

## Key Technical Details

- `LSUIElement=true` in Info.plist hides Dock icon (menu bar only)
- Gamma stays black as long as the process runs; killing the app restores normal display. `setBlack` verifies per-display success and sets `isBlack` only when **every** display went black (empty display list or partial failure keeps it false so the poll retries; re-blacking an already-black display is idempotent). **`restore()` gates on `gammaTouched`, not `isBlack`** — a partially-failed `setBlack` leaves `isBlack` false while some displays ARE black; gating restore on `isBlack` would leave them black until process exit. `reassertBlackIfNeeded` (hot-plug/wake) likewise drops `isBlack` back to false on any failure so the poll's `setBlack` retries, instead of pretending success
- Bundle ID: `com.sz.bento`
- Login start is owned by `SMAppService.mainApp` (menu toggle surfaces `.requiresApproval` as a distinct "待系统设置批准" state that deep-links to Login Items); the legacy LaunchAgent plist `~/Library/LaunchAgents/com.sz.bento.plist` is unloaded and deleted by a one-time migration on launch
- Code signing (`build_app.sh`): self-signed identity in a dedicated keychain; the keychain password is random, stored only in gitignored `.bento-codesign/keychain-password` (0600) — a legacy hardcoded password lives in public git history, so old keychains are migrated in place via `set-keychain-password` (cert unchanged → TCC grants survive). Private key/p12 are deleted from disk after import (an EXIT trap covers failed runs). If the keychain exists but the identity can't be found, the script REFUSES to rebuild (that would rotate the cert and void Accessibility/Input Monitoring grants) unless `BENTO_REBUILD_CODESIGN=1`
